# Add the backend environment template

## Goal

Create a local `backend/.env` starter file with editable values for the required backend configuration so the user can fill in their own credentials and database URL.

## Scope

- Include the backend variables documented in the root README: `PORT`, `NODE_ENV`, `FRONTEND_URL`, `DATABASE_URL`, `BETTER_AUTH_SECRET`, `BETTER_AUTH_URL`, `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`, `UPLOADTHING_TOKEN`, `RAZORPAY_KEY_ID`, `RAZORPAY_KEY_SECRET`, `RAZORPAY_WEBHOOK_SECRET`, `RESEND_API_KEY`, `GEMINI_API_KEY`, and `INNGEST_DEV`.
- Do not invent, copy, or store real secrets. Make placeholders visibly editable.
- Keep `backend/.env` ignored by Git.
- Update backend setup instructions so the user can install/start after filling the template.
- Confirm there are no backend-authored `.ts` or `.tsx` source/config files left.
- Explain that `backend/generated/prisma/**/*.d.ts` files are generated by Prisma Client for type declarations, not application source. Do not delete them: Prisma regenerates them, and they are part of its generated client output.
- Do not change application logic, API behavior, frontend files, or database schema.

## Edge cases

- Prisma loads `DATABASE_URL` from `backend/.env` during dependency installation/client generation; the file must define the key. Use a clear local-only MongoDB placeholder the user can replace.
- Preserve `.env` ignore rules and do not stage or commit the local environment file.

## Done when

- `backend/.env` exists locally with the documented keys and no actual credentials.
- `npm install` can run Prisma client generation with the placeholder database URL.
- The backend development command remains `npm run dev`.
- No backend-authored TypeScript files remain; generated Prisma declaration files are identified and retained.
